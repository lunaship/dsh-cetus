## 1. 目标、范围与完成标准

本次改造要解决的问题是：不同页面分别决定标题、间距、控件和表面材质，导致它们虽然共用部分 token，仍然像不同的产品。

统一后的方向是：**冷灰底色、清晰内容、轻薄玻璃操作层，以及固定的动作与状态语义。** 页面可以因任务不同而有不同布局，但相同用途的元素必须使用相同规则。

### 1.1 改造范围

- 任务首页：标题、电脑状态、工作区筛选、待处理内容、进行中与最近任务、新任务入口。
- 对话页：导航、正文、工具与思考内容、输入区、键盘与流式状态。
- 新任务：对话页草稿态、继续上次任务、工作区选择、智能体预设。
- 设置：首页与现有二级页、分组列表、选择行、开关、返回导航。
- 设备：首次配对、已配对设备状态、从设置进入、独立入口与设备弹层。
- 共用内容：筛选控件、按钮、状态、菜单、底部弹层、对话框、空态、错误与加载状态。
- 大屏：已有常驻侧栏与双栏工作区使用相同的组件和材质规则。
- 工程约束：设计文档、组件入口、相关回归检查、截图预览与 Linux 基线。

### 1.2 功能边界

保留现有产品能力和数据关系。设备页仍服从当前单设备模型；本方案不增加多设备仪表盘、底部主导航、后台接口或新的权限能力。

概念示意只展示五类主页面。里面的电脑名、时间、任务数、连接方式和设置项是示例内容，不构成新增字段要求，也不能据此删掉实际页面已有的设置和操作。

本轮写作只生成这份 Markdown。后续实施不需要改插件、Relay、手机协议、正式签名或版本号；若实现时发现确实依赖这些范围，应单独记录依赖，不把它们混入视觉改造。

### 1.3 最终完成标准

1. 五类主页面以及它们的二级页使用统一的导航、字体、间距、控件和状态规则。
2. 本文问题清单中的每一项都有对应代码变化或明确的验证结论。
3. 玻璃的背景采样、模糊、折射与回退路径能够在目标系统上正确运行。
4. 用户原有的阅读、输入、审批、工作区选择、设置和设备流程可用。
5. 本地门禁、Linux 截图、实际设备交互和视觉审查分别留有证据。
6. 文档与代码一致，不再保留互相冲突的视觉规定。

## 3. 统一设计规则

### 3.1 视觉方向与参考的使用方式

采用现有 DeepLinks 冷灰与品牌蓝，保持面向开发工作的清晰信息密度。参考 lody 的玻璃分层和操作反馈（输入聚焦形变首轮不做，R6）；导航与业务仍按 Android 和本项目结构设计。

修改现有视觉合同的“唯一方向”段落：保留 Material 3 的结构与无障碍要求、现有色源与品牌语义；把“lody 只能作为问题样例”的旧限制替换为本次明确允许的材质与交互参考。新设计值首先进入共用规则，页面不能单独增加一套规格。

### 3.2 页面骨架与导航密度

所有页面共享以下结构：

```text
系统栏（由明确的一层消费 inset）
页面导航（返回/上下文、标题、可选副标题、页面动作）
内容区（共享边距、分组、列表或正文）
底部操作（需要时出现；计入内容避让）
系统手势区 / 键盘避让
```

具体规格：

| 项目 | 目标规格 | 实施约束 |
|---|---|---|
| 页面标题 | 标准页 20sp / 26sp SemiBold；聊天 17sp / 24sp SemiBold | 标准页用 `DshType.headlineMedium`，聊天用 `DshType.titleLarge`；首页为「DeepLinks + 状态点」品牌顶栏（R1、R2） |
| 导航密度 | 标准页 `Standard(64.dp)`；聊天与首页 `Compact(56.dp)` | 统一由 `NavDensity` 枚举管理，杜绝单一硬编码；动态累加 `statusBars` 得到内容区避让（R3、R17） |
| 导航图标热区 | 至少 48 × 48dp | 图标本身为 16–20dp |
| 副标题 | 12sp / 18sp | 只显示有用的电脑、工作区或状态，不为填空加入重复品牌文字 |
| 手机页面边距 | 左右 16dp | 页面结构只施加一次 |
| 内容组间距 | 24dp | 通过组间距区分信息，不在每个控件四周加同样空白 |
| 分组内部边距 | 16dp | 由分组组件负责，子列表不再重复增加相同外层边距 |
| 列表最小行高 | 52dp | 多行内容和大字号允许增高 |
| 大屏普通内容 | 最大宽度 720dp | 工作区双栏与聊天宽度沿用现有自适应结构，单独验证阅读宽度 |

### 3.3 对齐与边距所有权

统一两级对齐线：

- **页面内容线：** 距屏幕左右边缘 16dp。正文、容器外边缘与独立控件按这条线排布。
- **容器内容线：** 容器再向内 16dp。分组标题与对应分组的内容起点对齐；有 leading 图标时，图标槽与文字槽由同一列表组件计算。

执行要求：
1. `DshPageScaffold` 负责页面边距策略，或把策略作为 `PaddingValues` 传给列表；同一边距不能同时在父容器和列表内消费。
2. `DshGroupCard` / `DshListRow` 只保留一层共用的行内边距。
3. 分隔线起点从同一份图标槽与文字槽计算，不能独立写常量。
4. 首页与聊天去掉各自的页面级补偿常量。
5. 新任务画布使用与对话内容一致的页面坐标；输入框内部留白不得再次转换为草稿外边距。

### 3.4 排版

| 用途 | 目标 | 现有入口 / 实施方式 |
|---|---|---|

| 重点内容标题，例如审批摘要 | 17/24，SemiBold | `DshType.titleLarge` |
| 列表主标题 | 16/22，Medium | 在共用列表角色中集中映射（R7） |

## 4. 液态玻璃设计与技术方案

### 4.1 参考边界与库约束

借鉴 lody 的操作层材质与边界；焦点合拢动效首轮不做（R6）。
Android 沿用 Backdrop 1.0.6。该库 `lens` 仅在 API 33+ 支持，参数单位为 **px**，形状必须是 **`CornerBasedShape`**（圆角形状），矩形会抛异常（R10）。

### 4.2 三种表面用途

| 用途 | 设计 | 典型位置 |
|---|---|---|
| 清晰内容面 | 稳定底色，无折射 | 正文、代码、设置行、长菜单、设备信息 |
| 导航玻璃 | 较浓底色、适量模糊、很弱边缘分层；全宽矩形不做透镜 | 页面顶栏与导航操作区 |
| 浮动玻璃 | 圆角浮岛：外圈边缘高光、轻折射与柔和阴影；**输入框本体用接近实色的面**（0.92/0.94，R5） | 聊天输入区外圈、附件入口、发送按钮、少量浮动控件 |

### 4.3 调参与动态负载保护

| 参数 | 导航玻璃 | 浮动玻璃 |
|---|---|---|
| 模糊半径 | 16dp 起 | 12dp 起 |
| 底色浓度，浅 / 深 | 0.84 / 0.88 起 | 外圈 0.68 / 0.76 起；输入框本体 0.92 / 0.94 起（R5） |
| 折射高度 / 折射量 | 0 / 0 | 8dp / 12dp 起，限制在轻档（R10） |
| 色散 / 深度效果 | 关闭 / 关闭 | 关闭 / 关闭 |
| 高光与阴影 | 关闭 | 边缘轻高光，柔和微阴影 |

**高频打字负载抑制（R16）**：
流式输出（`isRunning && isStreaming`）期间，背景源每秒多次重绘。此时浮岛的 `lens` 着色器临时降级为静态普通模糊（`blur`），文本生成结束自动恢复，避免长文本持续流式下 GPU 发热掉帧。

### 4.4 背景采样与浮岛布局防御

1. 采样源挂在内容层，与操作层同级，避免递归采样。
2. 顶部和底部高度回填滚动内容区，保持 `FollowBottomChromeGrowth`。
3. **输入浮岛高度防膨胀机制（R11、R15）**：
   - 排队消息条（`QueuedPromptsStrip`）与上下文条（`ComposerContextStrip`）合并进浮岛内部。
   - 当排队消息数 > 1 时，收拢为单行指示器（如 `+2 条排队中`），点按展开详情。
   - 浮岛容器设置 `maxHeightIn(max = 240.dp)` 且上限不超过屏幕可视高度的 35%，防止软键盘弹起后过度压迫消息区。
4. 吸顶目标摘要（`ChatStickySummary`）属于顶部内容层，不做玻璃。

### 4.5 系统能力与回退

| 环境 | 行为 |
|---|---|
| Android 13 / API 33+ | 导航模糊；圆角浮层轻折射与高光；流式按 R16 动态保护 |
| Android 12 / API 31–32 | 背景模糊与普通圆角表面，不调用折射 |
| API 26–30 | 主题中的稳定表面，保持相同尺寸与交互 |
| 预览 / layoutlib / 省电模式 | 稳定静态表面回退，文字对比度优先 |

## 5. 逐页设计与验收

### 5.1 任务首页
顶栏保持「DeepLinks + 状态点」单行（R1），改用共用导航组件的紧凑档（56dp）。工作区筛选采用共享菜单胶囊（14sp）。待处理内容内联卡片保持诚实降级（Outline 按钮）。新任务入口使用墨色实心浮动按钮。

### 5.2 对话页
顶栏紧凑档（56dp、17/24 `titleLarge`，R2）。聊天页保持白底（R4）。输入区为圆角浮岛，输入框本体接近实色，内部包含排队条防膨胀与上下文条（R15）。流式输出执行 GPU 自适应保护（R16）。

### 5.3 新任务草稿态
与对话页共用顶栏与底部输入区。草稿入口（继续上次、工作区、智能体预设）贴合输入区上方，工作区“更多”常驻行尾。

### 5.4 设置及二级页
采用标准页导航（最小 64dp、20/26 `headlineMedium`，R2）。分组列表统一为 52dp 行高。开关开启态采用 `inkFill` 轨道 + `onInk` 拇指（R8）。

### 5.5 设备、配对与设备弹层
从设置进入显示返回；作为冷启动根页面不显虚假上一页。深层直达时若返回栈为空，按 R18 兜底回退到 `AppRoute.HOME`。重命名、重新检查等入口位置保持完整。
