## 验证环境的版本边界（重要）

本轮把结论打在了正确的基线上，但**有一个边界必须说明**：

| | 版本 | 我能验到吗 |
|---|---|---|
| 我的隔离实例（CLI `dsh`） | **0.1.5-rc.3** | ✅ 全部真机验证都在这个基线上 |
| 本仓兼容基线（`docs/COMPATIBILITY.md`） | **0.1.7-alpha.1** | ❌ 本机没有这个版本的包（profile 里没有 DSH 依赖，均来自 CLI 自身；npm registry 也取不到），**无法在此验证** |

最直接受影响的是**手机接管审批**：在 rc.3 上「`approval/request` 钩子一次都不触发」（两轮探针实测），
所以 `/requests` 永远为空、接管分支不可达；而 0.1.7-alpha.1 带真正的插件面变更，**接管是否可达未知**。
App 侧两态都按 `takenOverByPhone` 分支，因此**在两种基线上都正确**：接管成功就出可交互卡，否则降级。
`awaitingInput` 走历史推导（`approval/asked` 无配对 `approval/decided`），两种基线上都成立。

**仍待验（都不是我能单方面完成的）**：
- 04 / 14 看改动真机：需要**有改动服务**的宿主（桌面基线）——rc.3 的 web profile 不发 `workspace/changes`；
- 06 通知的锁屏批准/拒绝：依赖接管成立，且要在 0.1.7-alpha.1 上复验；
- 11 平板整页：需要平板或大窗口折叠形态。
