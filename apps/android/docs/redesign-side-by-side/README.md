# 设计稿 ↔ 实现 并排对照

由 `设计稿/截图/*.png`（左）与我们的截图墙（右）拼接而成，用于方案阶段 10 第 4 项
「与设计稿并排」的可离线部分。生成脚本见本文件末尾。

## 怎么看这些图

**首页、看改动、设置、深色这几组是「同类可比」的**：我们的墙渲染的就是那一屏的完整内容，
所以左右差异基本等于实现差异。

**对话页那一组不可直接下结论**：`ChatFeedScreenshotTest` 渲染的是**逐条消息**（`MessageItem`），
而设计稿画的是**组装后的整页**（过程折叠行已收起、正文、改动卡、轮末行、底部输入区）。
所以「过程折叠行 / 改动卡 / 底部一行小字」在右图里看不到，并不是没做——它们由
`process row`、`changes card`、`chat bottom` 三组墙分别覆盖。要得到可比的整页图，需要新增一面
「整屏对话墙」（`ChatFeed` + 输入区），这件事还没做。

## 复现

对照图由一段一次性脚本生成（读两处 PNG、等比缩放到统一高度、并列并加标签），
没有进仓库的构建流程——它是给人看的产物，不是门禁的一部分。要重跑时按上表把
「设计稿文件名 → 墙名」配对即可；墙的路径是
`app/src/screenshotTestDebug/reference/dev/deeplinks/screenshot/<测试类>/<墙名>_*.png`。

## 一次值得记下的教训

我第一次看这批对照图时，把「进行中行没有已运行时长」当成了实现缺陷并写进 README。追查后
发现是**截图墙样例数据不真实**（`updatedAt = 0L`，于是所有行的时间位都渲染成空）造成的假象：
实现里那一行的时间是算了的。样例数据失真会让墙「看起来」暴露问题、实际掩盖问题——两面都危险。

修法：SidebarWall 的样例改用相对当前时间的真实时间戳（进行中 = 3 分钟前，最近 = 26 小时前），
现在墙上能同时看到「3 分钟 / 2 分钟前 / 昨天」三种相对时间形态。

## 对话页的组件拼版（`03-对话页_整页对照（拼版）.png`）

没有整页截图墙之前，我先做了一张**拼版**：左边是稿 03 的整页，右边把三面已有墙
（过程折叠行 / 改动卡 / 底部区）按顺序堆起来。**它不是整页截图**，标题里写明了；但已经能逐元素比对，
并且立刻暴露出两处真实差异：

1. **过程折叠行的口吻不对**。稿 03 写「已完成工作 · **编辑了 79 个文件**」，我们写
   「已完成工作 · **Read (2)**」——用的是工具名与调用次数，不是「改了多少文件」。方案 5.2 的原文
   就是「编辑了 N 个文件」。要改需要从工具调用的参数里数出被改动的文件（插件侧
   `produced-files` 那套逻辑已经有，App 侧还没有）。
2. **底部一行小字里的 `+250 −50` 该撤掉**。改动卡进消息流之后（阶段 5.3 已完成），这个行数统计
   在底部就是重复的；我在阶段 5 的提交里写过「等 5.3 的改动卡进消息流后由它接管（届时删）」，
   现在到点了。

另外两处是**有意的差异**，不是缺漏：稿 03 的「下一步建议胶囊」按方案 D3 v1 不做；稿里的输入条
只有「回复，或用 / 调用指令 + 麦克风」，我们的是真实输入条（带模型 / 模式 / 上下文占用 / 发送），
功能更多。

## 整屏对话墙（已做，取代上面的拼版）

`03-对话页_整页对照.png` 现在是真正的整页：用 `LazyListScope.chatMessageItems(...)` 组装分组后的
消息流 + 底部区，`ChatFeedActions` 用 `PreviewHost` + 空回调搭桩件。它证明了三件事：

1. **分组渲染在整页里确实生效**：过程折叠行收成一行「已完成工作 · read_file」，不再是逐条工具行。
2. **底部一行小字里的 +A −D 已撤掉**（改动卡接管），只剩「● 电脑名 在线 ··· N 轮 · N 步 · N 令牌」。
3. **代码块长行的疑点已查清**：一度看起来被右边缘截断，实际是 `horizontalScroll`（可以拖），
   不是硬裁；但稿 03 的代码块是**自动换行**的，所以照稿改成换行——真机上不用拖才能看全一行代码。

**仍缺一件事**：整页墙的样例里没有 `workspace/changes` 消息，所以**改动卡没出现**在整页图里
（它由 `changes card` 那面墙单独覆盖）。要让整页图与稿 03 完全同构，需要给样例补一条改动消息。
